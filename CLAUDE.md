# Claude Clubhouse

A Claude Code function-hooks plugin (a "mod"). The plugin is the `clubhouse/` folder; the repo root holds docs only. Load the `plugin-authoring` skill before editing: it names this build's API declarations.

## Commands

- `claude plugin validate clubhouse` after every edit. It must pass.
- `claude plugin test clubhouse` before every commit. It draws the band and every room on desktop and terminal.
- `helper/build.sh` after changing `helper/WindowTint.swift`. `window-tint --list` prints the on-screen windows for checking geometry.

## Rules the validator enforces

- `$` may only be passed to a function declared at the top of the same file. Never import a function that takes `$`.
- State atoms are declared in the file that uses them: `atom({ plugin: 'clubhouse', key: '...' } as const, initial)`. Shared defaults live in `hooks/lib/defaults.ts`.
- Every state key is declared in `types/index.d.ts`, which exports types only. `prefs` is `Shaped<Prefs>`: bump `PREFS_SHAPE` in `lib/defaults.ts` when `Prefs` changes in a way the old shape cannot be read as, so a live session that reloads never reads it. A new field that every reader takes with `??` (like `palette.text`) needs no bump, and not bumping keeps the live session's settings.
- One hook per event without a matcher: one `session.start` (in `hooks/register.tsx`; startup work for a new feature goes there), one `turn.complete` (`usage.tsx`), one `command.run` (`commands.tsx`, which counts every command and answers `/clubhouse`), one `tool.call` (`tools.tsx`), one `tool.describe` (`recipes.tsx`; it runs for every tool, so it checks the name before reading state).
- Matchers use string literals (`requestId: 'clubhouse'`), not imported constants.

## Adding a feature

1. Create `hooks/features/<name>.tsx` exporting `<name>(on: On)`.
2. Add one line to `hooks/register.tsx`.
3. Declare any new state in `types/index.d.ts`.
4. A feature with its own screen is a room: add it to `ROOMS` in `hooks/lib/defaults.ts` and render pane `clubhouse-<name>`; the home screen and `/clubhouse <word>` pick it up.
5. A feature on the bar is a bar item: add it to `BAR_ITEMS`, `DEFAULT_BAR` and `BarLayout`, and draw it in `piece()` in `hooks/features/band.tsx`. The Bar layout tab picks it up.
6. Remove it from `PLANNED` in `home.tsx` and add a test in `tests/`.

## Conventions

- `hooks/lib/` is pure: no `$`, no hooks. `clawd.ts`, `icon.ts` and `color.ts` import nothing, so `node` can run them directly for previews.
- Only `Button` is clickable; an `Svg` is a picture, so pair an icon with a `Button`.
- A pane that shows engine lists (`$.ui.panes()`, `$.agent.list()`) reads the `pulse` atom, and whatever changes those lists bumps it, so the pane redraws.
- Text the Clubhouse colors itself takes `look.ink` (the `ink` from `makeParts`): the user's Text color, or dark or light by `inkOn(background)` when that is automatic. `inkOn` is the one rule for the flip (`DARK_INK_FROM` in `lib/color.ts`); the helper's own fallback only serves hand-written configs.
- Everything the Clubhouse shows respects `prefs.isEnabled`.
- The strip above the prompt is called the Toolbar in everything the user reads (room title, buttons, notes, `/clubhouse toolbar`); the code still says `bar` (`band.tsx`, `bar.tsx`, `BarItemId`). Keep it quiet: new toolbar items default to hidden.
- An `Svg` cannot be pressed and a `Button`'s face is a string, so the Clubhouse icon on the toolbar is a picture with a one-glyph button beside it; an icon that is itself the button is not possible.
- Form fields live in module variables (`draft` in `agents.tsx`), not state, so typing does not redraw the pane.
- A room's frame uses `borderStyle: 'bold'` because he wanted it thicker. One bordered Box inside another does not make a thicker line: the two lines sit a cell apart and read as a double rule (tried 2026-10-03). Sections in a pane are bordered cards. `makeParts(elements, prefs, surface)` in `hooks/lib/parts.tsx` gives `card`, `note`, `plain`, `meter`, `ink`, `frame`, `picture`, `swatch` and `look`; use it in every new room.
- Panes are narrow and a cell is not a fixed pixel width on desktop: never use fixed-width columns. Put a button on one line and its description, wrapped, on the next, with `gap={1}` between entries.
- Every feature with a screen is a room that opens as its own tab, including features that also sit on the bar.
- A `$` helper needed in several files is copied into each (see `summarize`); keep its logic in a pure `lib/` function so the copies stay a few lines.
- Hidden skills are enforced in three places in `commands.tsx`: `command.describe` (slash menu), `prompt.attachment` for `skill_listing` (what Claude is told) and `tool.call` for `Skill` (what Claude can run). Keep all three in step.
- Design follows `DESIGN.md` at the repo root. Mods cannot set a font on `Text` (the app's own font is used), so headings are serif SVGs from `makeParts` (`title`, `heading`, `card`); never hand-roll a heading. Borders are hairlines in Cloud Dark; clay is for headings and the primary action only.
- Every surface accepts `Svg`, and the terminal draws only its alt text. Decide with `e.surface !== 'terminal'` (`canDraw`), not with `'Svg' in elements` alone.
- Tool rules are enforced by the one unmatched `tool.call` hook in `tools.tsx`; it fails closed (no answer means deny) and ignores `prefs.isEnabled` on purpose.
- Recipes (`lib/recipes.ts`, `features/recipes.tsx`) are tools registered as `mcp__clubhouse__<name>` at session start and on save. Their names are not literals, so no matcher can serve them: the same unmatched `tool.call` hook in `tools.tsx` answers them after the Tool rules, asking `$.tool.check` first because a hook that answers skips the engine's own permission step. A blank `{word}` in the command becomes a positional parameter (`scriptOf`, quote-aware), so what Claude fills in is one argument and never shell code; keep it that way. A plugin's own `$.tool.call` does not reach its own hooks, so the room's Try button runs the command itself. There is no unregister: a deleted recipe is re-registered with a "deleted" description and refused until the next session. The unmatched `tool.describe` hook asks for recipe tools to be listed in front of ToolSearch; the desktop app still listed one as deferred on 2026-10-03, and it was callable either way.
- Night watch (`lib/watch.ts`, `features/watch.tsx`): running watches live in `$.state`, never `$.store`, because the store is shared by every session and each would run them. Saved watches are only settings, so they are in the store (`SAVED_WATCHES_KEY`). One timer in `session.start` (`patrol` in `register.tsx`, every `WATCH_POLL_MS`) is the only thing that runs a check: it claims a due watch by moving `nextAt` on first, so nothing runs twice, and "Check now" in the room only sets `nextAt` to 0. Timers are dropped on reload and re-armed there. All decisions are in the pure `stepOf` (fired or not, quiet, busy, low usage, giving up, last check); the wake is `$.prompt.submit`, sent as the plugin's message with the command's output marked as data.
- Spend cap (`lib/cap.ts`): enforced in the one `agent.spawn` hook in `agents.tsx`, before `next(e)`; the setting is `prefs.spendCap` (0 is off) and sits in the Usage room. The plugin's own dispatch from Agent HQ is counted in the module variable `ownDispatches` so the user's own click is never capped. Lifting the cap is session state (`capLiftedUntil`), not a saved setting.
- Toolbar layout rules are in `lib/toolbar.ts`: every item has a size (`ITEM_SIZE`, shortcuts by label length) and a row holds `ROW_CAPACITY`; `arranged()` is the only way an item is shown or changes row, so a full row sends it elsewhere or adds a row (up to `MAX_ROWS`). A new toolbar item needs: `BarItemId`, `BarLayout`, `DEFAULT_BAR`, `BAR_ITEMS`, `ITEM_SIZE` and a branch in `piece()`; `mergePrefs` and `withBarCount` follow `BAR_ITEMS`. Saved layouts and color presets are in the store (`toolbarPresets`, `colorPresets`).
- Colors: the Background always covers the whole session (`reach` is fixed to `app`; the old button made things look broken) and the Text color is always automatic (`palette.text` is forced to null; the slot was confusing). A preset sets all three colors. Settings are the same in every session: each `keep` writes the store and the 30-second tick adopts a store that differs (`sameSettings`). The same tick restarts the helper if it stopped.
- Sidebar switch (Colors): `prefs.coversSidebar` sends `coverSidebar` and a `sidebar` color (the Background mixed toward black) in `tint.json`. The helper keeps a second set of layers masked to the sidebar strip with that deeper target (`sidebarStages`), so the session list reads as its own panel; one flat color over the whole window looked like a tint again on dark colors, and a shade only 28% deeper looked filmy, so under light text the sidebar is 55% toward black on every color, and under dark text (a light Background) it is the Background 30% toward white with no hue turn (a darker, turned sidebar was jarring on manilla) (the Forest preset is the look he called just about perfect: near-black with a hint of the hue beside a rich main area). The sidebar's hue is also turned 14 degrees (`sidebarOf`: warm hues toward red, the rest toward violet), so it reads as a neighbouring color and not as the same one under a shadow.
- The `AbovePrompt` hook returns only the toolbar. Nesting `await next(e)` (the app's own row: branches, pull requests) inside the toolbar's tree made the whole toolbar vanish on desktop on 2026-10-03, although the tests passed (their bottom is a plain Box). The app's own row is therefore hidden while the toolbar shows; a way to show both is still open.
- Weather (`lib/weather.ts`): place from `ipwho.is` or Open-Meteo's geocoder, forecast from Open-Meteo, one 15-minute timer (`skyCheck`), icons drawn as SVG from the user's own sketch (sun and lightning yellow, rain and snow blue, cloud outlined in the text color).
- The helper only covers Claude windows that are not inside another Claude window: a file dialog or sheet is left alone and cut out as an occluder. It writes what it covers, and why it exits, to `~/.claude/clubhouse-helper/tint.log`; read that first when the color disappears.
- A sent prompt's row is opaque to a mod (`next(e)` is an engine reference) and holds the app's own time, copy, rewind and expand controls under the text, so `frameRow` must wrap the whole row; pulling the border up cuts those controls. A long prompt's bubble takes 85% of the row, so the border stands off its left side by the other 15%: the engine refuses an engine node under a Box with `width` or `overflow` (tried 2026-10-03), so that gap cannot be clipped away. The border has no padding of its own.
- Ticker (`lib/ticker.ts`) and Live sports (`lib/sports.ts`) read unofficial feeds with `$.http.fetch`; both feeds answer 403 without a browser-style `User-Agent` (`FEED_HEADERS`). ESPN refuses date ranges, so the room fetches day by day. Each has one timer armed in `session.start` (`priceCheck` every 15 seconds, `scoreCheck` every 10, in `register.tsx`) that only fetches while its toolbar item is shown (or the Ticker room is open). The score feed refreshes about every 2 seconds (`cache-control: max-age=2`). Every session runs its own timers, so prices go through the store (`QUOTES_KEY`): a session takes a price another one fetched within the last poll instead of asking again, because Yahoo answers 429 when asked too often; favorites are fetched only while the Ticker room is open, and a price older than two minutes is drawn dim. `$.http.fetch` returns text only, so team logos are fetched with `curl` into `~/.claude/clubhouse-helper/logos/`, read back with `$.fs.read(..., { as: 'bytes' })` and embedded in the score Svg as data URIs. Under the helper a logo is redrawn first so its own colors show: `window-tint --pixels <png>` prints the picture as hex RGBA, `redrawn` in `lib/tone.ts` runs `pixelFor` on every color, and `lib/png.ts` writes an uncompressed PNG. A color that is nearly strong enough to be kept (Auburn's navy) is drawn a touch stronger (`vivid`) so the kept layers leave it whole. The `logos` atom is keyed by team and colors (`logoSlot`), so a color change redraws within one score check. Colored `Text` on the toolbar is pre-compensated with `drawnFor(look.tone, clearOn(...))`.
- Draw it: nothing in a pane can be drawn on (an `Svg` runs no script), so `helper/DrawPad.swift` is a second small AppKit program (`draw-pad`, built by `helper/build.sh`). The toolbar button runs it with `$.process.run` (up to ten minutes); Send prints the PNG's path and the mod fills the prompt with it. Sketches are temporary: `prompt.submit` notes any sketch path under `~/.claude/clubhouse-helper/sketches/` in the prompt, and the `turn.complete` of that prompt's turn removes the file (`dueSketches` compares the submit time with the turn's start, so a prompt queued behind a running turn keeps its sketch until its own turn ends). A prompt that says to keep the sketch is left alone.
- Safeguard warning and handoff prompt (`lib/guard.ts`) both live in the one `prompt.submit` / `turn.complete` / `session.measure` set in `usage.tsx`. The warning only warns: it answers `{ drop }` and refills the prompt when the user chooses to edit, and it must never suggest wording that hides what is being asked. The handoff row is drawn by `band.tsx` from the `handoff` atom and submits `HANDOFF_PROMPT` after the next main turn completes.
- Fonts (`lib/fonts.ts`): only what the Clubhouse draws as SVG can change font, because a mod cannot set a font on `Text` or on a `Button`: the headings always, and the toolbar's text (`words()` in `band.tsx`) whenever a font other than the default is chosen. Buttons and the live score stay as they are. `prefs.font` picks one of `FONTS` (fonts already on a Mac; an SVG drawn as an image cannot load a web font), each with a `widen` factor so `serifSize` still fits. The describe and design-file paths ask a small model for a name from that list only. Colors and Fonts are marked `isLook` in `ROOMS`: they open from the home screen's top row, not the Rooms list.
- Session notes (`lib/notes.ts`, `features/notes.tsx`): waiting notes are in the store; the one `session.start` claims the notes that fit a session's folder, but only when the session is new. A hot reload fires `session.start` again, so the `hasBooted` atom (state survives a reload) tells the two apart. Claimed notes ride on the session's first prompt as `context` in the one `prompt.submit` hook in `usage.tsx`. A plugin's `$.session.append` cannot be answered in tests (it rejects before any mock), so "Give to this session" is only checked for its refusal path.
- Release helper (`lib/ship.ts`): `/ship` and `/clubhouse ship` are answered in the one `command.run` in `commands.tsx`. It refuses off `main`/`master` or with uncommitted changes, and asks with `$.ui.ask` before the tag, push and `gh release create`, because those leave the machine.
- Zen mode was tried and dropped on 2026-10-03: hiding `ToolUse`/`ToolResult`/`ToolGroup` rows leaves blank rows inside the desktop app's own activity groups, and the group lines and thinking summaries are not render sites. The app's Transcript view (Normal) already folds tool calls; point the user there.
- Button keys must be unique within a pane: give a second listing of the same items its own key prefix.
- `Button`, `Input`, `Select` and `Markdown` come from `makeParts`, never straight from `elements`: the wrapped versions add a backing chip when the user's background is in the opposite light/dark family to `prefs.appMode`, which keeps the app-drawn controls readable.
- What a mod can color: the bar, the rooms, and every conversation row. Rows are tinted by wrapping `await next(e)` in `tintRow` (`lib/parts.tsx`), never by redrawing them, so the app's own row features survive. The desktop app clips each row and panel to its own box: negative margins and absolute slabs do nothing there (tried 2026-10-03), so a mod cannot fill the gaps between rows.
- What a mod cannot color: the gaps between rows, the composer, the footer controls, the pane tab strip, the title bar and the sidebar. They are app chrome, not render sites. The app paints from two built-in sets of CSS variables and rejects the remote-debugging switch. Never patch the app, write its `developer_settings.json`, or script its window.
- The session area is colored by `helper/WindowTint.swift`, a small AppKit program installed as `~/.claude/clubhouse-helper/window-tint` by `helper/build.sh`. It puts a click-through window over each Claude window holding stacked backdrop layers, one color-matrix filter each (layers clamp between stages, chained filters in one layer do not). A stage is `out = a * clamp(M x) + (1 - a) * x` with `a = clamp(affine(x))`; that alpha blend is the only non-linear step there is. The layers and filters are private Core Animation classes (`CABackdropLayer`, `CAFilter`); if they are missing the helper falls back to a plain translucent layer. A plain translucent layer, one affine remap, and a `curves` filter were all tried and rejected.
- For a dark app the stages are computed in `lib/tone.ts` (`helperStages`) and sent in `tint.json` as `stages`, `sidebarStages` and `kept`; the helper applies them as given, so its maths cannot drift from the mod's. The app's own surfaces are kept as steps, not flattened (flattening all five to one color and lifting every chip 25-40% toward white is what read as a milky film on blue, purple and pink, 2026-10-03): the main surface (level 21 of 255; 17 in the sidebar) is exactly the Background, and only text-bright greys (from level 62, fully by 110) are lifted to the Text color. With dark text (a light Background) the side pane, text box and buttons keep the app's own small steps toward the Text color. With light text those steps mix in the cream Text color and looked like a film (milky on blue, greyish on Grape and Plush), so a first stage sinks everything above the main surface by 23 levels and a last stage blends whatever lands beyond the Background into a panel shade of the Background's own hue (`panelShade`): 35% toward black on a mid-bright Background (`deepens`, luminance from 0.03), 16 points of HSL lightness up on a dark one. Buttons on a panel come out at about the Background. Levels are the desktop app's Code tab in dark mode; other tabs use other greys and get the nearest step.
- Three `kept` layers share a backdrop group with a capture-only layer under everything, so they read the untouched screen, and they put a pixel back as it was when two of its channels differ by more than 0.12 (fully from 0.25): window buttons, icons, logos, diff counts and anything the Clubhouse draws in a strong color stay true. A pale or grey color off the Background-to-Text line can therefore no longer be forced through; `pixelFor` then keeps its brightness right.
- A light app still uses the helper's own three stages (lift, remap, key from 226/255 up), mirrored in `lightAppStages`; untested until the app is actually switched to light.
- The helper leaves the app's sidebar alone and follows the app's mode: from the Claude app's `config.json` it reads `bootFrameLayout` (sidebar width, collapsed) and `userThemeMode`, nothing else (that file also holds sign-in caches: never read or print any other key), cuts the sidebar strip and any window in front out of the layers' mask, and resolves `system` against the macOS appearance. It reads `~/.claude/clubhouse-helper/tint.json`, which every `keep` in Colors rewrites (`helperConfig` in `lib/appColor.ts`), and exits when disabled or when Claude quits. The mod reads the same mode with one `sh -c` (`READ_APP_MODE`: `plutil -extract userThemeMode` plus `defaults read`) at session start, on every `keep` and on the 30-second tick; there is no dark/light button, because a wrong answer there broke every color.
- While the helper covers the session (`lookOf(prefs, surface).tone` is set), the Clubhouse paints no backgrounds and draws its own edges instead: a frame around the bar and each room, card hairlines, and a border around the user's own prompts (`frameRow`), each at a set contrast against the Background. Everything the Clubhouse draws with its own colors sits under the helper too, so it draws the color that comes out as the wanted one: `lib/tone.ts` runs the same stages (`shownFrom`) and solves them backwards (`pixelFor`: a table of greys for the brightness, the color offset on top, then a few Newton steps where a kept color is involved), in Display P3 like the screen. Pictures go through `picture(...)` from `makeParts`, which rewrites every `fill`, `stroke` and `stop-color` (`recolor`) to that color as a `color(display-p3 ...)` style with a hex fallback; `Box` colors take `look.edge` and `look.hairline`. Never hand an `Svg` or a color straight to the app from a room. The test holds `shownFrom` to screen readings: after changing a stage, capture the window with and without the overlay (`screencapture -R` and `screencapture -l <window id>`), compare shade by shade, and update the readings.
- What the helper cannot show: a grey or pale color on the far side of the Background from the Text color (darker than a dark background, lighter than a light one). Strong colors are kept as they are, so they always show. `clearOn` moves such a color toward the Text color until it shows (and until headings reach 3:1, Clawd 1.5:1), which is why Clawd and the meter turn paler on a mid-bright background with light text.
- To see Clubhouse drawings under the helper without waiting for the turn to end: write a page of them to the scratchpad, open it in the built-in Browser pane (it sits inside the Claude window, under the overlay), then `screencapture -x -R` the window and sample pixels.
- The exact repaint of the app itself is the user's own Developer Mode route under Advanced in Colors (`lib/windowTint.ts`); keep that snippet to one style rule.
- No unnecessary comments.

## Release

Feature branches; every merge to `main` gets a version tag and a GitHub Release with notes. Bump `version` in `clubhouse/.claude-plugin/plugin.json` to match.

## This repo while a session is developing it

Sessions load the Clubhouse from `clubhouse/` via `CLAUDE_CODE_PLUGIN_DIRS`. A session that created the mod under `~/.claude/dev-mods/<session>/clubhouse` keeps its own copy; sync it with `rsync -a --delete clubhouse/ <that folder>/` after edits.
